# 核桃记账产品与技术设计

日期：2026-09-19  
状态：Cloudflare 架构修订版，待用户审阅

## 1. 项目目标

核桃记账是一款面向个人、家庭和小型共享场景的跨平台记账 App。产品参考口袋记账的高效记账体验，但使用原创品牌、视觉和代码实现。

首版同时支持 Android 与 iPhone。所有日常功能在 App 内完成，不建设 Web 管理后台，不包含广告、会员购买、理财资讯和付费订阅。

项目成功标准：

- 用户可以在断网状态下完成记账和查询。
- 记一笔操作集中在同一页面，分类、金额、时间、账户、成员和备注触手可及。
- 数据通过 Cloudflare 无服务器后端跨设备同步。
- 多用户可以加入共享账本，并按角色协作。
- 金额、账户余额和统计结果保持一致且可追溯。

## 2. 技术选型

| 层级 | 技术 |
|---|---|
| 移动客户端 | Vue 3 + TypeScript + Ionic Vue + Capacitor |
| 构建工具 | Vite |
| 本地数据 | SQLite（原生端）+ IndexedDB（浏览器开发与预览） |
| 状态管理 | Pinia |
| 数据校验 | Zod，共享客户端与接口数据结构 |
| 云端 API | Cloudflare Workers + TypeScript + Hono |
| 云数据库 | Cloudflare D1（SQLite 语义） |
| 图片与导出 | Cloudflare R2 私有存储 |
| 定时任务 | Cloudflare Cron Triggers |
| 密钥管理 | Workers Secrets |
| 部署 | Wrangler；无需 Docker、Nginx、Go 服务或独立数据库服务器 |

客户端最终安装为 Android APK/AAB 和 iOS App，不以网页作为正式交付形态。Ionic 页面运行在系统 WebView 中，核心记账页使用自定义组件、固定数字键盘和受控动画，避免普通网页表单感。高频数据先读写本地 SQLite，网络请求不得阻塞记账操作。

体验验收标准：点击数字键、分类和快捷属性后，界面应在下一帧反馈；快速记账页不得弹出系统软键盘；在约 10,000 条本地流水的基准数据下，账单列表采用分页或虚拟滚动并保持可连续滚动；保存本地账单不依赖网络，正常设备上的交互动画以 60 FPS 为目标。最终以中低端 Android 真机和至少一台 iPhone 的性能测试结果为准。

首版不引入 Durable Objects。共享账本通过增量拉取、前台恢复同步和手动刷新保持一致；只有后续明确需要多人实时协作时才评估 Durable Objects。

## 3. 产品信息架构

App 使用四个底部主导航和一个中央快速记账按钮。

### 3.1 账单

- 本月收入、支出和结余
- 月度预算进度
- 按日期分组的账单流水
- 搜索和组合筛选
- 账单详情、编辑与删除

### 3.2 统计

- 日、月、年度收支趋势
- 收入与支出分类占比
- 同比、环比、日均和月均消费
- 从图表下钻到账单明细

### 3.3 账户

- 总资产、总负债和净资产
- 现金、银行卡、信用卡、支付平台及自定义账户
- 账户转账与余额调整
- 借入、借出和分次还款

### 3.4 我的

- 账本、分类和标签
- 预算与周期账单
- 数据导入、导出和备份
- 登录设备、安全设置和同步状态

## 4. 快速记账设计

快速记账是产品的核心体验，采用分类区与专用键盘组合，不使用普通表单式录入。

页面结构：

1. 顶部切换支出、收入和转账。
2. 分类直接排列在独立区域中，主要分类不隐藏在“更多”入口后。
3. 分类数量超出可用空间时，只滚动分类区域。
4. 金额栏、快捷属性和专用数字键盘固定在页面下部。
5. 快捷属性包含日期时间、付款账户、消费成员和备注。
6. 键盘支持数字、小数点、退格、加法和减法。
7. 提供“完成”和“保存并继续记一笔”。

分类、金额和快捷属性的选择均不离开当前页面。图片凭证、标签、报销和不计入预算等低频属性可以通过扩展面板设置。

## 5. 用户与认证

系统支持多用户，但不开放无条件注册。

- 用户通过注册邀请码、用户名和密码注册。
- 注册邀请码由管理员生成，可设置有效期和最大使用次数。
- 用户名全局唯一。
- 密码使用 Workers Web Crypto 支持的 PBKDF2-HMAC-SHA-256 加盐派生；参数写入摘要记录并可逐步升级。认证实现需在 Workers 免费档 CPU 限制下进行真机和线上基准测试，不得以明文或快速哈希替代。
- Access Token 有效期 30 分钟。
- Refresh Token 有效期 30 天，并与设备绑定。
- 支持查看和退出已登录设备。
- 首版忘记密码由管理员执行重置，不依赖短信或邮件服务。

## 6. 账本与成员权限

个人账本也使用统一的账本成员模型，只是初始仅包含创建者。

角色权限：

| 角色 | 权限 |
|---|---|
| 所有者 | 管理账本、成员、角色、分类、账户、预算和全部账单；转让所有权 |
| 可编辑成员 | 查看并新增、修改账单；访问统计与账户数据 |
| 只读成员 | 查看账单、账户、预算和统计，不可修改 |

规则：

- 所有者通过账本邀请码邀请成员。
- 邀请码可设置有效期、使用次数和默认角色。
- 加入采用预览与确认两步。
- 移除成员后立即失去账本访问权限。
- 已移除成员创建的历史账单保留。
- 所有者退出前必须转让所有权或删除账本。
- 成员加入、移除、角色变化和账单删除写入操作日志。

## 7. 核心数据模型

所有账本业务数据必须携带 `ledger_id`。主要数据表如下：

| 数据表 | 用途 |
|---|---|
| `users` | 用户身份、密码摘要、状态与个人设置 |
| `devices` | 登录设备、Refresh Token 和同步信息 |
| `invite_codes` | 用户注册邀请码 |
| `ledgers` | 账本名称、币种、所有者和账期设置 |
| `ledger_members` | 账本成员和角色 |
| `ledger_invites` | 共享账本邀请码 |
| `accounts` | 现金、银行卡、信用卡及其他账户 |
| `categories` | 收入和支出分类、排序与归档状态 |
| `tags` | 自定义标签 |
| `transactions` | 支出、收入、转账和退款 |
| `transaction_members` | 账单与消费成员的关联 |
| `transaction_tags` | 账单与标签的关联 |
| `attachments` | 图片凭证元数据 |
| `budgets` | 总预算和分类预算 |
| `loans` | 借入与借出 |
| `loan_repayments` | 分次还款记录 |
| `recurring_transactions` | 周期账单规则 |
| `sync_changes` | 账本增量同步序列 |
| `operation_logs` | 关键操作审计日志 |

金额统一以整数“分”存储，不使用浮点数。

## 8. 账户余额与转账

账户余额由流水重建：

```text
初始余额 + 收入 - 支出 + 转入 - 转出 + 余额调整
```

缓存余额用于提升查询性能，但不能成为唯一可信数据。

转账通过 D1 `batch()` 在同一数据库内原子执行，生成转账主记录、转出流水和转入流水，三者必须同时成功或同时失败。退款保留与原始账单的关联，不直接篡改历史金额。

## 9. 本地优先与同步

App 的写操作先提交到本地 SQLite 和 Outbox，界面立即显示结果，再异步上传 Workers API。浏览器开发模式使用 IndexedDB 适配器，但不作为移动端正式数据存储。

每条记录包含：

- 客户端生成的 UUID
- `ledger_id`
- `version`
- `created_by` 与 `updated_by`
- `created_at` 与 `updated_at`
- `deleted_at`
- `client_updated_at`
- `server_revision`

客户端额外维护 `sync_status`、`base_version`、`local_updated_at` 和重试次数。

同步流程：

1. 本地事务保存业务数据和待上传操作。
2. 客户端批量调用 `sync/push`。
3. Worker 校验成员权限、记录版本和幂等键。
4. Worker 使用 D1 原子批处理提交数据、同步变更和账本 revision。
5. 客户端按上次 revision 调用 `sync/pull`。
6. 客户端在单个本地事务中合并增量数据。

自动同步触发条件包括网络恢复、App 回到前台、手动刷新和新增数据。同步失败不阻塞本地使用。

## 10. 冲突处理

- 修改记录时上传 `base_version`。
- 服务端版本等于 `base_version` 时正常保存。
- 服务端版本更高时返回 `409 Conflict`。
- 客户端展示本机版本和服务端版本，以及修改人与修改时间。
- 用户选择保留本机版本或使用服务端版本。
- 首版采用整条记录选择，不做逐字段自动合并。
- 删除使用墓碑记录同步，避免其他设备重新上传已删除数据。
- 删除与修改同时发生时必须显式解决冲突。

## 11. API 设计

统一前缀为 `/api/v1`，由 Hono 路由，响应包含业务码、消息、数据和 `request_id`。

主要接口组：

- `/auth`：注册、登录、刷新 Token、退出和设备管理
- `/ledgers`：账本和成员管理
- `/ledger-invites`：邀请码预览与加入
- `/transactions`：账单 CRUD、退款和转账
- `/accounts`：账户和余额调整
- `/categories` 与 `/tags`：分类和标签
- `/budgets`：预算
- `/loans`：借贷和还款
- `/recurring-transactions`：周期账单
- `/reports`：统计报表
- `/attachments`：图片上传凭证与确认
- `/sync`：增量上传、拉取、状态和冲突解决

新增和同步接口必须接受幂等键，网络重试不得重复创建账单。列表与同步接口必须分页并限制单次返回量，避免 D1 大范围扫描和 Workers 响应体膨胀。

## 12. 图片凭证

图片经客户端压缩后上传到私有 R2 存储：

1. App 将压缩图片上传到受鉴权的 Worker 路由。
2. Worker 限制文件大小并校验扩展名、MIME 类型和文件头。
3. Worker 将文件写入 R2，并在 D1 创建附件记录。
4. 客户端收到附件 ID 后，将其关联到账单。

读取图片时使用短期签名地址，不提供永久公开 URL。后端校验文件大小、扩展名、MIME 类型和文件头。

## 13. 删除与归档

- 账单采用软删除，以便跨设备同步。
- 被历史账单引用的账户和分类只能归档，不能直接物理删除。
- 软删除数据超过保留期限且不存在引用后，可由 Cron Trigger 定时清理。
- 操作日志不随业务记录删除。

## 14. 安全要求

- 所有生产接口必须使用 HTTPS。
- Token 通过 Capacitor 安全存储插件保存在 Android Keystore / iOS Keychain；浏览器预览不得存放生产 Token。
- 每次请求都按 `ledger_id` 验证当前用户的成员关系和角色。
- 登录、注册和邀请码接口在 Worker 中限流；必要时增加 Turnstile 防自动化攻击。
- 连续登录失败触发短期锁定。
- 日志不得记录密码、Token、完整账单备注和图片地址。
- R2 Bucket 默认私有，下载由 Worker 鉴权后返回短期访问地址或代理响应。
- D1 使用 Time Travel 作为短期恢复手段，并通过 Cron 定期导出关键数据到 R2；必须定期验证恢复流程。
- 所有 D1 查询使用参数绑定；每次业务查询都显式包含 `ledger_id` 权限边界。
- Cloudflare 免费额度接近上限时记录告警信息；超限或网络异常不得破坏本地账本，本地数据继续可用并等待下次同步。
- 用户注销时按约定删除个人数据，同时保留共享账本中依法或业务上需要保留的匿名化历史记录。

- 多设备管理

- 三级成员权限

## 16. 测试重点

- 金额精度与加减运算
- 转账事务与余额重建
- 不同角色的权限边界
- 邀请码过期、超次数和撤销
- 断网新增、修改和删除账单
- 多设备同步和同一账单冲突
- 删除墓碑同步
- 重复请求幂等处理
- 大量账单的列表和统计性能
- Android 与 iOS 安全区域和键盘布局
- 数据备份与恢复
- Workers 免费档 CPU 与请求额度基准
- D1 行读取、行写入和分页查询成本

## 17. 非目标

首版明确不包含：

- Web 管理后台
- 会员订阅和应用内购买
- 广告系统
- 理财产品和资讯社区
- 银行账户自动连接
- 短信和邮件验证码
- 直接复制口袋记账的商标、图标、主题素材或源代码
