## 自动复现的缺陷

用例位于 `apps/mobile/audit/behavior.test.ts`。金额单位为分。

| 编号 | 优先级 | 操作或输入 | 预期 | 实际 |
| --- | --- | --- | --- | --- |
| A01 | 阻断 | 输入 `10 + 2` 后走页面保存所用金额读取函数 | 1200 | 200，保存不结算表达式 |
| A02 | 阻断 | `10 + 2 + 3 =` | 1500 | 500，连续运算丢弃前项 |
| A03 | 高 | 输入 21 位整数 | 限制输入或拒绝非安全整数金额 | 返回超过 JS 安全整数范围的分值 |
| A04 | 高 | 上海时区同一天的两个时间：9/20 17:00Z、9/21 01:00Z | 同一日期分组 | 按 UTC 字符串切片，分成两天 |

另一个诊断用例确认：同一数据库内两本账的记录都会由 `listTransactions()` 返回。结合下面 B02 的页面代码，确认存在本地混账风险；没有据此证明服务器端越权。

## 修复与验收顺序

1. 数据正确性：金额运算、输入边界、当前用户和账本隔离、真实账本 ID、会话生命周期、同步状态。先让失败用例转绿，再验证真实保存链路。
2. 记账闭环：分类新增/改名/排序/归档，日期、账户、备注编辑；收支保存、编辑、删除；转账双账户与原子性。分类变更需要保留旧账单可解释性，不能简单删除关联记录。
3. 多用户共享：创建和切换账本、邀请、角色权限、移除成员、两用户双端同步与冲突恢复。
4. 真实展示：账单月份筛选、汇总、账户余额、统计、预算全部由实际数据生成；清除固定示例数据和误导状态。
5. 其余入口：周期账单、导入导出、设备管理逐项闭环，不能以空链接宣称实现。
6. 最终验收：至少两个隔离用户、两个账本，在 320px/390px 视口执行完整操作；刷新重登、断网重试、重复提交、时区边界、权限拒绝均要验证。

## 复现命令

在仓库根目录执行：

```sh
pnpm --filter @walnut/mobile exec vitest run audit/behavior.test.ts
pnpm --filter @walnut/mobile test
pnpm --filter @walnut/api test
pnpm --filter @walnut/contracts test
pnpm typecheck
pnpm build
```

浏览器脚本 `scripts/audit-mobile.cjs` 需要可用的 Playwright 和匹配 Chromium。它只访问本地预览、隔离浏览器存储，并拦截非本地网络请求，不会写入真实后端。它是初步冒烟脚本，尚未跑通；“点击后 DOM 变化”也不等于完整业务验收。默认输出到 `/tmp/walnut-mobile-audit`，可用 `AUDIT_OUTPUT` 指定路径；`PLAYWRIGHT_MODULE` 可指定已有 Playwright 模块路径。
